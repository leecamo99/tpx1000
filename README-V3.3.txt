TPX1000 V3.3 更新說明
=====================

新增：Gemini 多金鑰輪替

一、可以做什麼
--------------
1. 可輸入任意多支 Gemini 金鑰，一行一支。
2. 系統由上往下輪流使用，某支撞到配額上限就自動換下一支。
3. 全部金鑰都試過才回報失敗，不會一撞 429 就停住。
4. 每支金鑰各自記錄冷卻時間，到點自動解除。

二、怎麼設定
------------
1. 進入使用者專區，找到原本的 Gemini API Key 欄位。
2. 該欄位下方新增了「金鑰管理（可存多支，自動輪替）」按鈕。
3. 點開後在文字框一行貼一支金鑰，按儲存。
4. 清單會即時顯示每支的狀態，例如：

     1  ...Xk9Qw2   可用
     2  ...7fMpL1   冷卻中，請等 43 分鐘後再試
     3  ...bN3sR8   可用

5. 按鈕下方也有一行即時摘要，例如
   「目前存有 3 支金鑰，可用 2 支，其餘配額冷卻中」。
6. 原本的單一金鑰欄位仍可正常使用，
   按「儲存並測試 Gemini」時會自動把該支同步進輪替清單。
7. 舊有的 kinGeminiKey 在第一次開啟時會自動匯入，不必重貼。

三、輪替規則
------------
1. 收到 429 或 403 會立刻換下一支，不浪費時間在同一支上重試。
2. 每日配額用盡的金鑰冷卻 6 小時。
3. 每分鐘限流的金鑰，依 Google 回傳的 retryDelay 決定冷卻秒數。
4. 所有金鑰都試完之後，才改用備援模型 gemini-2.5-flash-lite 再跑一輪。
5. 網路錯誤或 5xx 仍是同一支金鑰退避重試 3 次，
   間隔 0.7 秒、1.4 秒，逾時 45 秒中止。
6. 任何一支成功回應，就清除該支的冷卻記錄。
7. 儲存時自動去除重複與空白行。

四、實測結果
------------
存入 5 筆（含 1 筆重複、1 筆空白）→ 去重後正確保留 3 支。

模擬 KEY_A 每日配額用盡、KEY_B 金鑰無效、KEY_C 正常：

  KEY_A@gemini-2.5-flash → KEY_B@gemini-2.5-flash → KEY_C@gemini-2.5-flash
  成功取回 {"root":"ok"}

只剩冷卻中的 KEY_A 時，訊息為：
  所有金鑰都已達配額上限。免費額度約於台灣時間下午四點重置

五、重要提醒
------------
同一個 Google Cloud 專案底下開出來的多支金鑰，不會增加額度。
免費配額是綁在專案上，不是綁在金鑰上。
要真正拉高上限，必須用不同 Google 帳號各自建立專案取得金鑰，
或直接在 Google AI Studio 開啟付費方案。
