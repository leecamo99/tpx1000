TPX1000 V3.1 更新說明
=====================

本版在 V3 之上，新增 AI 記憶輔助的圖片生成，並以最小尺寸儲存。

一、助記圖片
------------
1. 單字解說頁的「AI 記憶輔助」區塊，操作列新增「生成圖片」按鈕。
2. 必須先按「AI 記憶輔助」產生助記，有了圖像描述之後按鈕才會出現。
3. 圖片為手動觸發，不會自動全書生成。
4. 已生成過的字，按鈕會顯示「重新生成圖片」。
5. 圖片顯示在助記內容下方，點一下放大到 200px，再點一下縮回 96px。

二、尺寸最小化
--------------
1. 生成後立即用 canvas 置中裁切，縮到 96x96。
2. 轉成 WebP，品質 0.55；瀏覽器不支援 WebP 才退回 JPEG。
3. 只有縮圖會寫進 localStorage，原始大圖不保留。
4. 每張約 1 至 2.4 KB（base64 後）。
   以 5 MB localStorage 額度推算，約可存 2000 至 3400 個單字的助記圖。
5. 生成成功時會直接顯示該張圖片的實際 KB 數。

三、提示詞
----------
送出時自動加上固定尾綴：
minimal flat icon, single subject, solid background, no text, no letters, high contrast
扁平單一主體在 96px 下才辨識得出來，寫實照片縮到這個尺寸會糊掉。

四、關於 token
--------------
縮圖省下的是 localStorage 容量與頁面載入流量，不是 token。
圖片費用在送出請求當下就依提示詞與輸出圖片計價，
在本地縮小不會回頭影響已經產生的成本。
真正能省的是只對記不起來的字手動按生成，這點目前設計已經符合。

五、儲存位置
------------
沿用 V3 的 kinMnemo:<使用者>，圖片存在該單字物件的 img 欄位，
以「書籍/單字ID」分開，不會互相覆蓋。
按「刪除助記」會連同圖片一併刪除，你自己手寫的筆記不受影響。

六、金鑰與模型
--------------
沿用使用者專區既有的 Gemini 金鑰，不需另外設定。
圖片模型使用 gemini-2.5-flash-image。

七、快取
--------
sw.js 的 VER 由 kin-shell-v14 改為 kin-shell-v15。

八、驗證結果
------------
index.html 共 22 段 inline JavaScript，node --check 全部通過，0 錯誤。
sw.js 語法檢查通過。
無殘留 Git 合併衝突標記。
圖片模組確認載入順序在 KIN_MNEMO 之後。

九、沿用 V3 既有功能
--------------------
1. 閃卡例句限制 5 至 10 字、上限 12 字，並有 __kinTrimEx 前端守門。
2. AI 記憶輔助四項：字根拆解、聯想記憶、易混字比較、記憶圖像描述。
3. 加入筆記、重新生成、刪除助記三個操作。
